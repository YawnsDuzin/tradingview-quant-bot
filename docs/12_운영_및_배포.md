# 12장. 운영 및 배포

> 로컬에서 개발한 FastAPI 서버를 실제 인터넷에 배포하여 **24시간 자동매매**를 운영하는 방법을 배웁니다.

---

## 12.1 로컬 개발환경 → 실서버 배포 흐름

### 배포가 필요한 이유

로컬 PC에서는 다음과 같은 문제가 있습니다:
- PC를 끄면 봇도 멈춤
- 인터넷 연결 끊김 시 매매 불가
- 전력 소비 부담
- TradingView Webhook의 외부 접근 문제 (ngrok 필요)

**실서버 배포**:
- 24시간 가동
- 안정적인 네트워크
- 고정 IP + HTTPS
- 원격 모니터링

### 전체 배포 흐름

```
1. 로컬 개발 & 테스트
   └─ 모의투자 환경에서 충분히 검증

2. Git 저장소에 코드 푸시
   └─ .env 파일은 절대 푸시하지 말 것!

3. 클라우드 서버 선택 및 생성
   └─ Oracle Free / AWS EC2 / Vultr 등

4. 서버 초기 설정
   └─ 방화벽, SSH 키, 사용자 계정

5. 코드 배포 (Git pull 또는 scp)

6. 환경변수(.env) 서버에 설정

7. Docker 또는 systemd로 실행

8. Nginx + HTTPS 설정

9. TradingView에 실제 Webhook URL 등록

10. 모니터링 및 로그 확인
```

## 12.2 서버 옵션 비교

### 주요 클라우드 옵션

| 서비스 | 가격 | 사양 | 장점 | 단점 |
|--------|------|------|------|------|
| **Oracle Cloud Free** | **무료** | 1-4 vCPU, 6-24GB RAM | 영구 무료, 고사양 | 한국 리전 없음 |
| **AWS EC2 (t4g.nano)** | 약 $3.5/월 | 2 vCPU, 0.5GB RAM | 안정적, 한국 리전 | 트래픽 비용 |
| **Vultr** | $2.5~$6/월 | 1 vCPU, 0.5-1GB RAM | 저렴, 간단 | 한국 리전 없음 |
| **DigitalOcean** | $4~$6/월 | 1 vCPU, 0.5-1GB RAM | UI가 좋음 | 한국 리전 없음 |
| **NCloud (네이버)** | 약 10,000원/월~ | 1-2 vCPU | 한국 리전, 한국어 | 상대적으로 비쌈 |

### 초보자 추천: Oracle Cloud Free Tier

**장점**:
- **평생 무료** (Always Free)
- **고사양**: ARM 기반 4 vCPU + 24GB RAM 가능
- 한국에서 일본 리전 사용 시 지연 낮음

**단점**:
- 신용카드 등록 필요 (과금되지는 않음)
- 가입 과정이 다소 복잡
- 일본/싱가포르 리전 (한국 없음)

**추천 사용 사례**:
- 학습 및 테스트 단계
- 소규모 개인 퀀트봇 운영
- 비용 절감이 최우선일 때

> ⚠️ **주의**
> 무료 서버라도 **API 키 유출은 실제 자금 손실**로 이어질 수 있습니다.
> 보안 설정을 반드시 강화하세요.

## 12.3 Oracle Cloud Free Tier 서버 생성 (요약)

### 단계별 요약

1. **가입**: https://cloud.oracle.com 접속 → 계정 생성
2. **계정 인증**: 이메일, 휴대폰, 신용카드
3. **Region 선택**: Japan (Tokyo) 또는 Korea South (Chuncheon) 권장
4. **Compute Instance 생성**:
   - Shape: **VM.Standard.A1.Flex** (Always Free, ARM)
   - OCPU: 2, Memory: 12GB (무료 한도)
   - Image: **Ubuntu 22.04**
5. **SSH 키 생성 및 다운로드**
6. **Networking**: VCN 자동 생성, Public IP 할당
7. **Security List**: 22(SSH), 80(HTTP), 443(HTTPS) 포트 개방
8. **Instance 시작**: SSH 키로 접속

```bash
ssh -i ~/.ssh/oracle_key ubuntu@<public-ip>
```

## 12.4 서버 초기 설정 (Ubuntu 22.04)

### 12.4.1 시스템 업데이트

```bash

```

```bash
# UFW 활성화
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

### 12.4.3 사용자 계정 생성 (보안)

```bash
# 전용 사용자 생성
sudo adduser quantbot
sudo usermod -aG sudo quantbot

# SSH 키 복사
sudo mkdir -p /home/quantbot/.ssh
sudo cp ~/.ssh/authorized_keys /home/quantbot/.ssh/
sudo chown -R quantbot:quantbot /home/quantbot/.ssh
sudo chmod 700 /home/quantbot/.ssh
sudo chmod 600 /home/quantbot/.ssh/authorized_keys

# 전환
su - quantbot
```

### 12.4.4 시간대 설정 (한국)

```bash
sudo timedatectl set-timezone Asia/Seoul
```

## 12.5 Docker + docker-compose 배포

### 왜 Docker인가?

- **환경 일관성**: "내 컴퓨터에서는 돌았는데..." 문제 해결
- **배포 간편**: 한 줄 명령으로 설치/업데이트
- **격리**: 시스템 라이브러리 충돌 방지

### 12.5.1 Docker 설치

```bash
# 공식 설치 스크립트
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 현재 사용자에게 Docker 권한 부여 (재로그인 필요)
sudo usermod -aG docker $USER
newgrp docker

# docker-compose 설치
sudo apt install -y docker-compose-plugin

# 확인
docker --version
docker compose version
```

### 12.5.2 `Dockerfile` 작성

프로젝트 루트에 `Dockerfile`을 생성합니다:

```dockerfile
# Python 3.11 slim 이미지
FROM python:3.11-slim

# 환경변수
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1 \
    TZ=Asia/Seoul

# 작업 디렉토리
WORKDIR /app

# 시스템 패키지 설치
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    curl \
    && rm -rf /var/lib/apt/lists/*

# 의존성 먼저 복사 (Docker 캐시 활용)
COPY requirements.txt .
RUN pip install --upgrade pip && pip install -r requirements.txt

# 앱 코드 복사
COPY ./app ./app

# 비루트 사용자 생성 및 권한 부여
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser

# 포트 노출
EXPOSE 8000

# 헬스체크
HEALTHCHECK --interval=30s --timeout=10s --start-period=30s --retries=3 \
    CMD curl -f http://localhost:8000/status/ || exit 1

# 실행 명령
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]
```

### 12.5.4 `docker-compose.yml`

```yaml
version: "3.9"

services:
  quantbot:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: quantbot
    restart: unless-stopped
    env_file:
      - .env
    volumes:
      - ./data:/app/data          # SQLite DB 영속화
      - ./logs:/app/logs          # 로그 영속화
    networks:
      - quantbot_net
    labels:
      - "com.project=quantbot"

  nginx:
    image: nginx:alpine
    container_name: quantbot_nginx
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro
    depends_on:
      - quantbot
    networks:
      - quantbot_net

networks:
  quantbot_net:
    driver: bridge
```

## 12.6 HTTPS 설정 (Let's Encrypt + Nginx)

### 왜 HTTPS가 필요한가?

- TradingView Webhook은 **HTTPS를 권장**
- API 키 및 민감 데이터가 평문으로 전송되지 않음
- 무료로 발급 가능 (Let's Encrypt)

### 12.6.1 도메인 준비

먼저 **도메인**이 필요합니다.
- **Cloudflare**: 무료 DNS + 도메인 등록 (약 $9/년)
- **가비아**: 한국 도메인 등록 업체
- **Namecheap**: 저렴한 해외 도메인

도메인이 있다면, A 레코드로 서버 Public IP를 연결:
```
quantbot.example.com   →   123.45.67.89
```

### 12.6.2 Nginx 설정 (`nginx/conf.d/quantbot.conf`)

```nginx
# HTTP → HTTPS 리다이렉트
server {
    listen 80;
    server_name quantbot.example.com;

    # Let's Encrypt 검증용
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

# HTTPS 서버
server {
    listen 443 ssl http2;
    server_name quantbot.example.com;

    # Let's Encrypt 인증서
    ssl_certificate /etc/letsencrypt/live/quantbot.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/quantbot.example.com/privkey.pem;

    # SSL 설정
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # 보안 헤더
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000" always;

    # 요청 크기 제한
    client_max_body_size 1M;

    # FastAPI 프록시
    location / {
        proxy_pass http://quantbot:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 타임아웃
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }

    # Webhook IP 제한 (TradingView 공식 IP만 허용)
    location /webhook {
        allow 52.89.214.238;
        allow 34.212.75.30;
        allow 54.218.53.128;
        allow 52.32.178.7;
        deny all;

        proxy_pass http://quantbot:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### 12.6.3 Let's Encrypt 인증서 발급

```bash
# Certbot 설치
sudo apt install -y certbot

# 임시로 Nginx 컨테이너 중지 (80 포트 점유 해제)
docker compose stop nginx

# 인증서 발급 (standalone 모드)
sudo certbot certonly --standalone \
  -d quantbot.example.com \
  --email your-email@example.com \
  --agree-tos --non-interactive

# Nginx 재시작
docker compose start nginx
```

### 12.6.4 인증서 자동 갱신

```bash
# crontab 편집
sudo crontab -e

# 매월 1일 새벽 3시에 갱신 시도
0 3 1 * * certbot renew --quiet && docker compose -f /home/quantbot/tradingview-quant-bot/docker-compose.yml restart nginx
```

## 12.7 모니터링 및 로그 관리

### 12.7.1 로그 확인


### 12.7.2 로그 로테이션 설정

Docker 로그가 무한히 커지는 것을 방지합니다.

`docker-compose.yml`에 추가:

```yaml
services:
  quantbot:
    # ... 기존 설정
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "5"
```

### 12.7.3 프로세스 모니터링

```bash
# 컨테이너 상태
docker compose ps

# 리소스 사용량

# 컨테이너가 재시작되는지 확인

```

### 12.7.4 텔레그램 알림 활용

9장에서 만든 텔레그램 알림으로 다음을 받으면 좋습니다:

- ✅ 앱 시작/종료 알림
- 🟢 매매 체결 알림
- ⚠️ 에러 발생 알림
- 📊 일일 리포트 (잔고, 수익률)
- 🔄 서버 재시작 알림

### 12.7.5 간단한 헬스체크 스크립트

```bash
#!/bin/bash
# healthcheck.sh - cron으로 주기 실행

URL="https://quantbot.example.com/status/"
STATUS=$(curl -s -o /dev/null -w "%{http_code}" $URL)

if [ "$STATUS" != "200" ]; then
    # 텔레그램 알림 (BOT_TOKEN, CHAT_ID 사전 설정)
    MESSAGE="⚠️ 자동매매 봇 이상 감지! HTTP $STATUS"
    curl -s -X POST "https://api.telegram.org/bot$BOT_TOKEN/sendMessage" \
         -d "chat_id=$CHAT_ID&text=$MESSAGE"

    # 자동 재시작
    cd /home/quantbot/tradingview-quant-bot
    docker compose restart quantbot
fi
```

crontab 등록:
```bash
# 5분마다 실행
*/5 * * * * /home/quantbot/healthcheck.sh
```

## 12.8 PostgreSQL로 전환 (선택 사항)

SQLite는 간단하지만 **동시 쓰기에 취약**합니다. 프로덕션에서는 **PostgreSQL**을 권장합니다.

### docker-compose.yml에 PostgreSQL 추가

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: quantbot_db
    restart: unless-stopped
    environment:
      POSTGRES_USER: quantbot
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: quantbot
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - quantbot_net

  quantbot:
    # ... 기존 설정
    depends_on:
      - postgres
    environment:
      - DATABASE_URL=postgresql://quantbot:${POSTGRES_PASSWORD}@postgres:5432/quantbot

volumes:
  postgres_data:
```

### psycopg 드라이버 추가

```txt
# requirements.txt에 추가
psycopg[binary]==3.2.3
```
